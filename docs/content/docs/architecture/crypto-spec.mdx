## Overview

Kepr enforces high cryptographic standards for local secret storage and transit across socket boundaries.

---

## 1. Master Key Protection (Argon2id)

When `kepr lock` is executed, Kepr wraps the random 32-byte AES credential master key using **Argon2id** key derivation.

### Argon2id Parameters
- **Algorithm**: Argon2id (v0x13)
- **Memory Cost (`m_cost`)**: 64 MiB (65,536 KiB)
- **Time Cost (`t_cost`)**: 3 passes
- **Parallelism (`p_cost`)**: 1 thread
- **Salt**: 16 bytes CSPRNG
- **Key Length**: 32 bytes (256 bits)

### Envelope Format (`master.key.argon2id`)

Current format, `kepr_pw3` (T13.20). The cost is stored in the header, and
the header is the AES-GCM associated data, so it cannot be lowered unseen:

| Field | Type / Size | Description |
| :--- | :--- | :--- |
| **Magic Header** | 9 bytes ASCII | Literal `"kepr_pw3\n"` format identifier |
| **Memory (`m_kib`)** | `u32` Big-Endian (4 bytes) | Argon2id memory cost in KiB |
| **Time (`t`)** | `u32` Big-Endian (4 bytes) | Argon2id iterations (pass count) |
| **Parallelism (`p`)** | `u8` (1 byte) | Argon2id lane count |
| **Salt** | 16 bytes | CSPRNG random salt |
| **Nonce** | 12 bytes | AES-256-GCM initialization vector |
| **Encrypted Master Key** | 32 bytes + 16 bytes | AES-256-GCM ciphertext + 16-byte authentication tag |

A stored cost outside 8 MiB to 1 GiB, 1 to 10 passes and 1 to 8 lanes is
refused before any hashing, so a tampered file cannot make the daemon
allocate gigabytes. Older stores hold `kepr_pw1` (the same layout without the
cost fields and with empty associated data, at the fixed cost above); it still
opens and is rewritten as `kepr_pw3` after the next successful `kepr unlock`.
A FIDO2-protected store uses `kepr_pw2` (see the plan, T4.09).

## 2. Authenticated Encryption (AES-256-GCM)

Individual credential values are encrypted using **AES-256-GCM** with 96-bit nonces.

### Encryption Protocol
- **Cipher**: AES-256-GCM
- **Nonce**: 12 bytes generated per-credential operation via `/dev/urandom` / `getrandom`.
- **Authentication Tag**: 16 bytes (128 bits).
- **Associated Authenticated Data (AAD)**: Encodes `kepr-<uid>-<name>` to prevent credential renaming or cross-user transplantation attacks.

---

## 3. In-Memory Zeroization (`ZeroString`)

Secret buffers use `ZeroString` and `zeroize::Zeroizing` wrappers.

- **Automatic Wiping**: Heap memory allocated for secrets is explicitly zero-overwritten on `Drop`.
- **Compiler Optimization Barriers**: `zeroize::zeroize_volatile` prevents rustc / LLVM from optimizing away zeroization writes.
