## Master Key Management

### Locking the Store (Argon2id Passphrase Protection)

```bash
kepr lock
# Enter passphrase: ****
# Store locked with Argon2id + AES-256-GCM
```

This wraps the master key with a user-provided passphrase using Argon2id (64 MiB memory, 3 passes).

### Unlocking

```bash
kepr unlock
# Enter passphrase: ****
```

## Auditing Credential Access

### View All Operations

```bash
journalctl -t kepr-daemon
```

### Filter by Operation Type

```bash
journalctl -t kepr-daemon KEPR_OP=get          # Only fetches
journalctl -t kepr-daemon KEPR_OP=set          # Only stores
journalctl -t kepr-daemon KEPR_RESULT=fail     # Only failures
```

### Filter by User

```bash
journalctl -t kepr-daemon KEPR_UID=1000        # Specific UID
```

### Real-Time Monitoring

```bash
journalctl -t kepr-daemon -f
```

## Detecting Unauthorized Access

Watch for:

1. **Failed attempts**: `KEPR_RESULT=fail` with mismatched UIDs.
2. **Unusual credential access patterns**: Unexpected operations on sensitive secrets.
3. **After-hours access**: Compare audit timestamps to expected maintenance windows.

```bash
# Suspicious failed attempts
journalctl -t kepr-daemon KEPR_RESULT=fail --since "2 hours ago"
```

## File System Hardening

### Credential Store Permissions

```bash
ls -la /etc/credstore.encrypted/
```

**Expected**: `drwx------` (0700), owner `root:root`.

### Master Key File Permissions

```bash
ls -la /var/lib/kepr/
```

**Expected**: `drwx------` (0700), owner `root:root`.

---

## Network Isolation

The daemon listens on a **Unix domain socket**, not TCP. This prevents:

- Remote compromise via network attacks.
- Credential leakage over untrusted networks.

```bash
ls -la /run/kepr/kepr.sock
```

**Expected**: `srw-rw----` (0660), owner `root:kepr`.

## Periodic Credential Rotation

```bash
# List all credentials
kepr list --json | jq '.credentials[].name'

# For each critical secret, regenerate
kepr set OPENAI_API_KEY --generate
kepr set DATABASE_PASSWORD --generate --gen-kind pass
```

## Disaster Recovery

### Recovery kit (recommended)

Split the master key into shares and store them apart. Any *k* of
them rebuild the key; fewer reveal nothing.

```bash
kepr lock                                    # the kit needs a passphrase-protected store
kepr recovery-kit create --threshold 3 --shares 5 --out-dir /media/usb
```

Each share is one line like `kepr1-3-1-31b27750565eafdc-…`. The middle
field is the kit's fingerprint; shares from different kits don't mix.
Hand them to different people or places, and never keep them next to
the machine.

To recover, use a machine that has the old credential files but whose
master key is gone: the TPM was replaced, the key file was lost, or the
passphrase was forgotten.

```bash
kepr recovery-kit restore      # paste 3 shares, a blank line, then a new passphrase
```

The daemon rebuilds the key and checks that it opens the credential files
on disk. It then stores the key under the new passphrase. Restore refuses
while the current key still works, so it can't be used to re-key a healthy
store.

<Warning>
  The recovery kit is the only path by which master-key material leaves
  the daemon. That's why it needs the passphrase, refuses while agent
  sessions run, is root-only in system mode, and is audited
  (`KEPR_OP=recovery-kit`, `recovery-restore`).
</Warning>

### Backup Master Key

Pipe straight through encryption — never let the raw key touch disk
unencrypted, not even briefly:

```bash
sudo cat /var/lib/kepr/master.key | gpg --symmetric --cipher-algo AES256 \
  --output ~/kepr-master-key.backup.gpg
```

<Warning>
  Store `kepr-master-key.backup.gpg` offline (encrypted external drive,
  hardware token). Anyone who recovers this file *and* your `gpg`
  passphrase can decrypt every credential in the store.
</Warning>

### Export All Credentials

Same rule: encrypt on the way out, don't write plaintext and rely on
remembering to shred it afterward.

```bash
kepr --json list | jq -r '.credentials[].name' | while read -r name; do
  value=$(kepr get "$name" --quiet)
  printf '%s=%s\n' "$name" "$value"
done | gpg --symmetric --cipher-algo AES256 --output ~/kepr-export.txt.gpg
```

<Warning>
  If a tool in your pipeline truly requires a plaintext file on disk,
  write it to a `mktemp` file with `0600` permissions, use it
  immediately, then `shred -u` it in the same shell step — never leave
  a plaintext export resident, even under a "delete it later" plan.
</Warning>

### Restore from Backup

```bash
sudo systemctl stop kepr
gpg --decrypt ~/kepr-master-key.backup.gpg | sudo tee /var/lib/kepr/master.key >/dev/null
sudo chown root:root /var/lib/kepr/master.key
sudo chmod 0600 /var/lib/kepr/master.key
sudo systemctl start kepr
```
