# Kepr Codex and OMP integration review

**Review date:** 2026-11-07  
**Scope:** Codex and oh-my-pi (`omp`) integration failures reported in recent
Codex and omp session history, plus the related kepr gate, plugin, release, and
documentation paths.

## Executive result

The recurring failures split into two classes:

1. **Codex provider/resource state.** Kepr now validates Codex provider
   configuration, forces the configured provider through the local gate, removes
   cached login state from the protected invocation, and bounds the AgentRouter
   Responses retry.
2. **OMP conversation protection.** Signed reasoning is rejected rather than
   mutated. Tool-result and tool-argument content is redacted before a model
   request. Redaction now bounds hook children and deduplicates in-flight text;
   structured arguments preserve safe sibling fields.

No real credential values were read, printed, or included in this report.

## Recurring failure analysis

### Codex: AgentRouter Responses resource mismatch

**Symptom.** A resumed Codex conversation could receive a 400 resource/state
error when previous response or item identifiers were replayed to AgentRouter.
Manual probes without Codex client headers also returned `401 unauthorized
client`; that is a separate client-identification issue, not evidence that the
kepr credential was invalid.

**Current implementation.** `crates/kepr-gate/src/responses.rs` performs one
bounded retry for the exact resource mismatch. The retry:

- counts against the request limit;
- removes saved item identifiers only from self-contained items;
- preserves text, `call_id`, and encrypted reasoning;
- refuses chained/reference-only history and unknown item shapes;
- does not retry authorization or malformed-request errors.

`src/cli_agent_codex.rs` additionally validates the configured provider name,
sealed `env_key`, exact provider host, and restricted URL path. It rejects
alternate auth sources such as cached bearer/login configuration. The protected
argv sets an ephemeral credential store, the selected model provider, the local
gate URL, and the sealed environment-key name.

**Status:** **Fixed with bounded fallback.** The saved handoff records live
AgentRouter turns returning 200 and mock coverage for mismatch, persistence,
and retry limits. The exact historical upstream mismatch was not reproduced in
the review session, so the fix should not be described as a complete upstream
root-cause proof.

### OMP: signed thinking mutation

**Symptom.** Earlier OMP context redaction treated signed Anthropic thinking as
ordinary text. It changed the text while retaining the provider signature,
which violates the signed-block invariant and can produce an invalid-request
400.

**Current implementation.** The live plugin now detects signed thinking and
fails closed instead of returning edited text:

- `plugins/omp/kepr/index.ts:282-284` rejects signed thinking containing a
  detected secret shape;
- `crates/kepr-gate/src/prompt.rs` keeps signed thinking subject to blocking;
- unsigned text remains eligible for redaction.

**Status:** **Fixed in the user-owned worktree.** The prior test that expected a
retained signature after mutation must remain removed or changed to assert the
provider invariant: signed thinking is either unchanged or the request is
blocked.

### OMP: concurrent redaction process fan-out

**Symptom.** The nested `Promise.all` calls in the earlier plugin launched one
`kepr hook redact` child per uncached message or content block. A synthetic
probe observed one concurrent child per input message. Long resumed histories,
tool results, and tool arguments could therefore exhaust process or memory
limits, hit the five-second hook timeout, and replace valid context with
withheld markers.

**Fix.** `plugins/omp/kepr/index.ts` now admits at most eight redaction hooks at
once and keeps an in-flight `Map<string, Promise<CheckedText>>` so duplicate
text shares one child. The completed-result memo remains bounded at 256 values.

**Status:** **Fixed.** The regression feeds 32 distinct history messages and
observes no more than eight concurrent hook children.

### OMP: truncated PEM inside serialized tool arguments

**Symptom.** The redactor intentionally consumes the remainder after an
incomplete PEM header followed by a newline. Redacting a whole JSON-stringified
arguments object can therefore remove closing JSON syntax when a truncated PEM
appears before another field.

**Current implementation.** The plugin parses arguments first, redacts each
string leaf, and reserializes only when a string-form argument changed. Safe
sibling fields and non-string values remain structured; invalid JSON or an
unanswered safety check blocks the tool call.

**Status:** **Fixed.** The regression covers a truncated marker and verifies
that a safe sibling survives redaction.

### OMP: broken-pipe termination

**Symptom.** Hook/plugin output streams could terminate an OMP process with an
`EPIPE` exception when the consumer closed the pipe first.

**Current implementation.** `plugins/omp/kepr/index.ts` installs stdout/stderr
error handlers and suppresses only `EPIPE` uncaught exceptions. Other exceptions
remain visible. The release notes document the broken-pipe protection.

**Status:** **Fixed and scoped.** The handler does not blanket-suppress
unrelated failures.

### Git credential host-name collision

**Finding.** `git_cred_name` previously folded every non-alphanumeric host
character to `_`. Distinct hosts such as `a.b-c` and `a-b.c` therefore selected
the same credential. The raw/legacy Git helper path could then return or delete
the wrong value.

**Fix.** `crates/kepr-core/src/providers.rs` keeps dotted legacy names stable
but appends a lowercased byte encoding for hosts containing other punctuation.
The regression covers both colliding shapes and the existing port form.

**Status:** **Fixed in the live worktree.** The targeted release test passed:
`cargo test --release -p kepr-core git_over_https_on_github_com`.
Existing stored credentials for hyphenated hosts need to be stored again under
the collision-free name; dotted names retain their previous names.

## Boundary and secret-handling review

The following controls were confirmed in the current source or saved test
results:

- `kepr agent run` obtains only sealed credential metadata and starts a local
  gate; the harness receives placeholders and gate URLs.
- `src/cli_agent_run.rs` removes adapter-controlled credentials, proxy values,
  database variables, AWS session values, and values matching key shapes from
  inherited environment data before `env_clear`/exec.
- Codex refuses `--no-sandbox`; the protected Codex path requires the sandbox.
- `src/cli_hook.rs` blocks revealing kepr verbs and key-shaped tool input, and
  `redact` returns replaced text without returning matched values.
- `crates/kepr-core/src/redact.rs` handles complete and truncated PEM blocks,
  JSON escapes, source-span preservation, and Unicode surrounding text.
- The OMP hook treats a timeout as a block. A missing kepr executable remains
  allowed because the gate and sandbox are the primary boundary.
- Plugin installation embeds the plugin and skill source in the binary so the
  installed plugin matches the reviewed kepr version.
